# FinalDiagrams v0.4 implementation contract

Deliver a reusable library, local CLI and portable agent skill. The default artifact is one editable offline HTML file. Keep code modular internally; compile runtime on library release, never require consumers to build a generated document.

## Shared project format

`{ schemaVersion: 1, id, title, subtitle?, revision: 0, entities: [], relations: [], diagrams: [], blocks: [] }`

- Entity: `{ id, kind, name, summary?, description?, technology?, group?, fields?: Member[], methods?: Member[], source?: { path, line?, url? }, tone? }`. Kinds: actor, service, module, library, database, queue, external, class, interface, table, state, choice, initial, final. `module`/`library` require runtime 0.2+; state kinds require 0.3+. Tone is neutral/info/success/warning/error. Re-export to upgrade older HTML when introducing new kinds.
- Member: `{ id, name, type?, purpose?, details?, visibility?, values?: { [customColumnKey]: string } }`.
- Relation: `{ id, source, target, label, kind, description?, sourceMember?, targetMember?, sourceMultiplicity?, targetMultiplicity?, tone? }`. Kinds: calls, async, reads, writes, association, inheritance, implementation, composition, aggregation, dependency, transition. Tone has the same enum as entities. Transitions connect state kinds; no incoming initial/outgoing final transitions.
- Diagram: `{ id, type, title, description?, entityIds: string[], relationIds?: string[], direction?: 'RIGHT'|'DOWN', notation?: 'uml'|'plain', columns?: [{key,label}], positions?: {[entityId]: {x,y}}, groups?: [{id,label,description?}], messages?: Message[] }`. Types: system, class, sequence, state. State views contain state kinds and transition relations only, default DOWN, and support cycles/self-loops. Groups are visual containers, not composite-state semantics.
- Message: `{ id, from, to, label, kind: 'sync'|'async'|'return', description?, phase? }`. Ordered messages define sequence semantics, never infer runtime calls from static relations. Phase is an optional fragment/group caption, not a claim of formal UML alt/par support.
- Block: heading `{id,type:'heading',level:1|2|3,text}`, prose `{id,type:'prose',markdown?:string,content?:object}`, diagram `{id,type:'diagram',diagramId}`, callout `{id,type:'callout',title,text,tone?:'info'|'warning'}`, code `{id,type:'code',language?,text}`, image `{id,type:'image',src,alt:string,caption?:string}`. Prose has exactly one of markdown or Tiptap JSON content. Preserve arbitrary arrangement and number of blocks. A rich-text editor changes a prose block to content and removes markdown.
- Image blocks embed offline raster data only: `src` is a `data:image/(png|jpeg|webp|gif);base64,...` URL with valid base64 and a matching raster file header. SVG, remote URLs, and executable URLs are rejected. Empty `alt` is permitted for decorative images; meaningful images should include useful alternative text. Captions are plain text.
- IDs globally unique among project entities, relations, diagrams and blocks; member/message IDs unique in their parent. All references validated. Unknown fields preserved across reads/edits/exports for forward compatibility. No executable user data. Safe handling of script-closing text is mandatory.

## Modules and ownership

- `src/model.mjs`: environment-neutral validation helpers. `validateProject(project)` returns `{valid,errors,warnings}` with diagnostics `{path,message}`; `assertProject(project)` throws with readable diagnostics; `parseProject(text)` validates and returns object.
- `src/export.mjs`: Node export/extract; CLI `bin/finaldiagrams.mjs` provides validate, export, extract, update, serve. Build reads `dist/runtime.js` and `src/styles.css`.
- HTML uses `<script id="fd-project" type="application/json">...escaped JSON...</script>`, `<style id="fd-styles">...</style>`, and `<script id="fd-runtime">...runtime...</script>`. Runtime receives only source JSON; no external imports/network requests in portable output. Body has `<div id="app"></div>`.
- `src/diagrams.js`: exports `async renderDiagram(container, diagram, project, options={})`. Controllers include `destroy`, `fit`, `zoom`, `focus`, `clearFocus`, `exportSvg`, `relayout`, `refresh`, `getView`, `setView`, `getPositions`, `viewportCenter`, `requestAddNode` and `startConnection`. Callbacks include `onSelect`, `onInspect`, `onChange`, `onError`, `onConnect`, `onReconnect`, `onReorder`, `onRename` and `onAddNode`. The renderer changes `diagram.positions` for node moves; semantic gestures send callbacks for the root app to validate and commit. Hover circles, drag previews and inline rename inputs exist only in edit mode. Empty/invalid drops and Escape/pointercancel preserve the canonical model. SVG exports omit editing controls and transient highlights. Each canvas has its own camera, preserved across semantic refreshes. Use safe DOM/text APIs; shared dependencies may be bundled by esbuild.
- `src/app.js`: root application entry. Basic native rich-text editing; semantic inspector for entities, members, relations, messages, columns and tones. Search, theme, undo/redo, JSON import/export, HTML save, source view, connected sync. Compact unbranded toolbar with accessible icon actions, one title, useful navigation only; move file mechanics to About and keep actionable dirty/conflict feedback.
- Runtime source bootstraps from fd-project and exports `window.FinalDiagrams` with `getProject()` (clone), `setProject(project)`, `exportHTML()`, `mount(...)` if useful.
- Browser save: serialize CURRENT canonical model into the ORIGINAL source template, not live DOM. On boot capture document.documentElement.outerHTML BEFORE mounting. Replace only fd-project block using escaped JSON; preserve runtime/css. Refresh model revision on canonical commits. Do not include transient selection/search UI in saved HTML.
- Connected local server API: GET `/api/project` => `{project,revision}`; PUT `/api/project` body `{project,baseRevision}` => `{project,revision}`; conflict 409 with current revision. GET `/api/events` SSE events `project` with `{revision}`. UI fetches only when served by this CLI (bootstrap marker `window.__FD_CONNECTED__ = true`); portable file must make zero network requests. Persist atomically; invalid external JSON retains last-good model, emits error event. Server binds 127.0.0.1 and checks Origin on writes. Revision is server managed and monotonic.

## Delivery and testing

- Build runtime once with esbuild IIFE (no module import at runtime). Package scripts: build, demo, test, test:browser.
- Sample `examples/backend-onboarding.json` is clearly fictional: order system, overview, sequence, classes with explanatory columns, information details, varied prose/code/callouts. Also `examples/dense-system.json` exercises 35+ entities without pretending a single full view stays readable at fit scale.
- The sole demo HTML output is `artifacts/all-diagrams.html`, generated from `examples/all-diagrams.json`. It covers all four types, grouped database tables and a dense overview. Automated browser fixtures, downloads and screenshots belong under `.cache/`, alongside their focused source examples in `examples/`.
- Core tests validate references, escape hostile text, extraction round trip, concurrent updates and malformed external input. Browser tests exercise actual visual prose/member edits, source import, HTML download/reopen, no network in file mode, layout/search, console errors and screenshots.
- Routing checks cover exact PK/FK row attachments, cardinalities outside cards, obstacle avoidance after dragging, and separate reciprocal state lanes. Inspect rendered Chrome screenshots at readable scale as well as Overview; passing geometry assertions alone does not establish visual clarity.
- Skill must preserve full requested document and reuse packaged runtime, never generate its own diagram JavaScript or force onboarding-only structure. Codex/Claude/Copilot packaging. No claim of compatibility tested unless actually exercised in that host.
